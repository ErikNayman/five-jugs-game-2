# «Каскад» на сайте: техзадание на интеграцию

Документ для разработчика сайта. Игра — один статический файл `cascade.html`. Сайт встраивает её, принимает от неё результаты, проверяет их на сервере и возвращает игроку место среди других игроков.

Главный принцип: **цифрам из браузера не доверять.** Сервер переигрывает запись действий игрока тем же движком, что и в игре, и сам считает годы, капитал и исход.

## 1. Что уже есть в репозитории

| Файл | Что это |
|---|---|
| `cascade.html` | Игра. Источник правды для движка и текстов. |
| `engine/flow-engine.js` | Движок для Node, генерируется из `cascade.html` командой `node tools/extract-engine.js`. Вручную не править. |
| `engine/example-result.json` | Настоящее событие результата, снятое в браузере. |
| `tools/verify-selftest.js` | Самопроверка: бот играет, честные результаты проходят, подделки отклоняются. `node tools/verify-selftest.js` |
| `i18n/ua.json` | Украинский словарь интерфейса. |

## 2. Встраивание игры

Рекомендуемый способ — `iframe`:

```html
<iframe src="/game/cascade.html?lang=ua" title="П'ять глечиків · Каскад"
        style="width:100%;height:100dvh;border:0" allow="clipboard-write; fullscreen"></iframe>
```

- `?lang=ua` или `?lang=ru` задаёт язык и запоминает его. Без параметра игра берёт язык браузера (`uk*` → UA, иначе RU). Игрок может переключить язык в самой игре.
- Прогресс хранится в `localStorage` игры (ключи `five-jars-*`). Сайту его трогать не нужно.
- Раздавать `cascade.html` с `Content-Type: text/html; charset=utf-8`. Внешних зависимостей у игры нет.
- В `cascade.html` есть константа `SITE_URL = ''`. Впишите адрес сайта, и игра будет добавлять ссылку в текст «Скопировать итог».

## 3. Событие результата: игра → сайт

Игра отправляет событие один раз, когда заканчивается партия в режимах «Экономический цикл» (`level: "endless"`) или «Жизненный путь» (`level: "life"`). Кампания (уровни 1–12) и «Испытания» событий не шлют.

Как получить:
- в `iframe`: `window.addEventListener('message', e => { if (e.data?.type === 'cascade:result') … })`. Проверяйте `e.source === iframe.contentWindow`;
- на той же странице: `window.addEventListener('cascade:result', e => e.detail)`.

Формат (`v: 1`):

```json
{
  "type": "cascade:result", "v": 1,
  "engine": 3, "rules": "3.4", "lang": "ru",
  "level": "endless",
  "seed": 4089917025, "code": "1VN1469",
  "week": "2026-W39",
  "opts": {},
  "log": [ { "t": 0, "f": "setValve", "x": ["income-savings", 0.25] }, "…" ],
  "claim": { "status": "lost", "time": 18.06 },
  "shown": { "years": 0, "real": 870, "peak": 870, "freedom": 0 }
}
```

| Поле | Смысл |
|---|---|
| `engine`, `rules` | Версия движка и правил. Проверять только движком той же версии правил (см. §7). |
| `level` | `endless` или `life`. |
| `seed` / `code` | Код сценария: число и его запись в base36. |
| `week` | Ключ ISO-недели, если это «Сценарий недели», иначе `null`. |
| `opts` | Для `life`: `{prof, goal, diff}`. Для `endless` пусто. |
| `log` | Все действия игрока со временем игры `t` в секундах: `f` — функция движка, `x` — аргументы, у `lifeChoose` ещё `pick`. |
| `claim` | Что утверждает клиент: исход `won`/`lost` и время окончания. |
| `shown` | Что игрок видел на экране. **Только для отладки, в рейтинг не брать.** |

Для `endless` исход `won` означает «Система построена»: игрок сам закончил, когда доход капитала покрыл расходы.

## 4. Проверка на сервере

```js
const E = require('./engine/flow-engine.js');
const v = E.verifyRun(payload);   // payload — событие из §3 как есть
if (!v.ok) reject(v.reason);
// v = { ok, status, time, years, real, peak, freedom, week, weekOk, dropped, subs, engine }
```

- `verifyRun` переигрывает партию с нуля по `seed`, `opts` и `log` и сравнивает с `claim`: исход должен совпасть, время — с точностью до 0,25 с. Для «Система построена» дополнительно проверяется, что в заявленный момент доход капитала действительно покрывал расходы.
- В рейтинг идут **только поля из `v`**: `years`, `real` (капитал в ценах начала игры), `peak` (пик капитала), `status`.
- `weekOk: true` — код сценария совпадает с заявленной неделей. Без `weekOk` результат в недельный рейтинг не принимать.
- Коды отказа: `no-payload`, `level`, `seed`, `claim`, `log-size`, `log-entry`, `status-mismatch`, `time-mismatch`.
- Скорость: партия на 13 игровых лет проверяется примерно за 160 мс, лимит — 60 лет, до ~0,7 с. Проверку лучше выполнять в очереди или воркере, а не в обработчике запроса.
- Проверка доказывает, что результат получен по правилам на этом сценарии. Что играл человек, а не бот, она не доказывает. Для учебной игры это приемлемо.

Неделю на сервере считать той же функцией: `E.isoWeek(date)` → `'2026-W39'`, `E.weekSeed('2026-W39')` → код. Принимать результаты текущей и прошлой недели: игрок мог начать в воскресенье вечером.

## 5. Рейтинг

Сравниваем только **«Сценарий недели»** (`level: "endless"`, `weekOk: true`). Условия у всех одинаковые, различаются только решения. «Жизненный путь» можно принимать и хранить, но не ранжировать: у игроков разные профессии и цели.

Порядок (лучше → хуже):
1. `status: "won"` («Система построена») выше любого `lost`;
2. среди `won`: меньше `years` — лучше; при равенстве больше `real`;
3. среди `lost`: больше `years` — лучше; при равенстве больше `peak`.

Процент: `beat = round(100 × (хуже + ½ · равных) / всех)`, где «все» — лучшие результаты разных игроков за неделю без текущего.

- Один игрок — один лучший результат за неделю. Идентификатор — случайный анонимный id, созданный сайтом (cookie или `localStorage` сайта).
- Меньше 50 результатов — процент не показывать. Игра сама напишет «сравнение появится, когда их будет 50», сайту достаточно отправить `n`.

## 6. Место в рейтинге: сайт → игра

```js
iframe.contentWindow.postMessage({ type: 'cascade:rank', beat: 73, n: 412 }, '*');
// или на той же странице: window.dispatchEvent(new CustomEvent('cascade:rank', { detail: { type: 'cascade:rank', beat: 73, n: 412 } }))
```

Игра показывает на экране итога «Твой результат лучше, чем у 73% игроков (412 результатов).» на языке игрока и добавляет строку в текст «Скопировать итог». Принимаются только числа: `beat` от 0 до 100, `n` от 0. HTML не вставляется. Сообщение нужно прислать, пока открыт экран итога этой партии: следующая партия сбрасывает место.

## 7. Версии правил

`rules` (сейчас `"3.4"`) меняется, когда меняется баланс или механика. Партию старых правил нельзя проверять новым движком — результаты разойдутся.
- Хранить `engine/flow-engine.js` для каждой версии `rules`, которую принимает сервер (например, `engines/3.4.js`).
- Неизвестную версию `rules` отклонять.
- Недельный рейтинг считать внутри одной версии правил.

## 8. Защита и приватность

- Лимит тела запроса — 1 МБ. `verifyRun` сам отклоняет запись длиннее 20 000 действий.
- Ограничение частоты: например, 30 результатов в час с одного id или IP.
- Персональные данные не нужны: хранить анонимный id, событие, итог проверки `v`, дату. Имена и почта для рейтинга не требуются.
- `lang` использовать только для статистики.

## 9. Как проверить интеграцию

1. `node tools/extract-engine.js` → свежий `engine/flow-engine.js`.
2. `node tools/verify-selftest.js` → «проверок: N прошло, 0 провалено».
3. `node -e "console.log(require('./engine/flow-engine.js').verifyRun(require('./engine/example-result.json')))"` → `ok: true, weekOk: true`.
4. Встроить игру в страницу, сыграть «Сценарий недели» до конца, убедиться, что сервер получил событие, `verifyRun` вернул `ok: true`, а в игре появилась строка с местом.
